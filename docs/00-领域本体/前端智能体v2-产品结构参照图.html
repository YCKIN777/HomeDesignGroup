家装前端智能体 v2 · 产品结构参照图
示意 · 探讨稿
参照系：LinkedNav（信号驱动的获客外联产品）× Pi 工作区（自建智能体架构）。核心原则三条：信号驱动（只追有信号的客户）· 人审后发（AI 起草，销售批准才发送）· 账号安全（轮换限速防封号）。
LinkedNav 产品模块 → 家装前端智能体模块
LinkedIn Profiles（账号池）
多账号连接·状态·运行中
→
账号池：企微 / 微信 / 抖音号统一管理
多销售轮换·每日限速·风控告警（防封号）
Campaigns（外联活动）
多活动·触达节奏·自动停止
→
获客活动：新盘交付期批量触达、转介绍回捞、老客激活、节点（量房/周年）营销
回复即自动停止序列
Prompts（提示词/话术）
场景模板·个性化
→
话术库：首联 / 跟进 / 邀约 / 回捞，按场景 + 客户上下文（楼盘·户型·预算）生成
Unibox（统一收件箱）
AI 起草→人批准→发送
→
统一收件箱：所有客户对话汇总；AI 起草回复，销售一键批准后发送
「人审后发」是红线
Social Listening（社交监听 98）
监测话题与意向
→
社交监听：小红书 / 抖音 / 大众点评——谁在问装修、谁发求助帖、谁评论竞品
Active Signals（活跃信号）
谁准备购买
→
活跃信号：留资 / 点赞 / 评论 / 私信 / 进店 / 看方案 → 评分 Agent 定级（A/B/C）
Contacts 99+ / Unlimited Leads
→
客户 CRM + 线索池（第一阶段两张主表）
MCP / API（对外工具接口）
80+ 工具·可被智能体调用
→
开放工具接口：获客数据、话术、派单对外可调用（对接派单 / 设计师系统）
Pi 工作区架构 → 支撑层（照着你的 Pi 来搭）
驾驶舱 Web UI
对话 + 客户列表 + 派单面板 持久记忆
客户档案 / 跟进日志 / 待办（pi-memory 式） 插件机制
渠道接入 / 知识库检索 / 数据库 浏览器扩展
网页拾取客户信息一键录入（page-picker 式） 一键部署
install/start 脚本（bat 式）
整体流转：信号/线索进入 → 评分分级 → 话术库起草 → Unibox 人工审批后发送 → 到店/谈单（谈单知识库支撑）→ 签约 → 派单给设计师。
借鉴 LinkedNav 的三条产品原则：① 信号驱动，不盲打；② AI 起草、人批准才发（这正好回答你之前问的"客服自主度"——全自动起草+采集，发送前人工把关）；③ 账号池轮换限速，保护销售微信号。
