# 家装 AI 智能体平台 · 领域本体 v0.1

> 状态：探讨稿 v0.1　|　更新：2026-09-28　|　存放：HomeDesignGroup/docs/00-领域本体/
> 本体 = 把家装领域的概念、关系、状态、规则显式写出来，作为平台的数据模型、Agent 分工、知识库分类的骨架。

## 1. 核心概念（类）

### 业务对象
| 概念 | 定义 | 关键属性（首版） |
| --- | --- | --- |
| 渠道 Channel | 线索来源 | 名称、投放方式、成本 |
| 线索 Lead | 未验证的潜在客户 | 手机号、来源、楼盘、留资时间、意向 |
| 客户 Customer | 已验证建档的客户 | 姓名、联系方式、需求标签、状态 |
| 项目 Project | 一个家装工程（本体中心） | 客户、户型、预算区间、风格、阶段 |
| 户型 Layout | 房屋结构 | 楼盘、面积、格局、户型图 |
| 方案 DesignPlan | 设计产出 | 平面图、风格、版本、状态 |
| 报价单 Quote | 金额测算 | 明细项、总额、折扣、版本 |
| 合同 Contract | 签约法律文件 | 条款、金额、优惠、收款记录 |
| 材料 Material/SKU | 主材辅材 | 品类、品牌、规格、单价 |
| 供应商 Supplier | 供货方 | 联系方式、价格、账期、到货 |
| 工地 Site | 施工现场 | 项目、地址、照片、日报 |
| 节点 Milestone | 工序/验收点 | 名称、计划时间、状态、验收清单 |
| 验收 Acceptance | 节点验收结果 | 检查项、结果、整改单 |

### 组织与平台
| 概念 | 定义 |
| --- | --- |
| 角色 Role | 销售 / 设计师 / 预算员 / 项目经理 / 工长 / 总监 |
| 环节 Stage | 获客 / 设计 / 预算 / 材料 / 工程 / 总监办 |
| Agent | 归集 / 评分 / 跟进 / 邀约 / 报价 / 签约 / 交接 / 总监办 |

## 2. 关键关系

| 关系 | 说明 |
| --- | --- |
| 渠道 → 线索 | 线索 来自 渠道 |
| 线索 → 客户 | 线索 转化（验证）为 客户 |
| 客户 1..n 项目 | 客户 拥有 项目 |
| 项目 - 户型 | 项目 关联 户型 |
| 项目 → 方案 | 项目 派生 方案（可多版本） |
| 方案 → 报价单 | 方案 对应 报价单 |
| 报价单 → 合同 | 报价单 锁定 合同金额 |
| 报价单 → 材料 | 报价单 引用 材料（明细项） |
| 材料 → 供应商 | 材料 来自 供应商 |
| 项目 → 工地 | 项目 包含 工地 |
| 工地 → 节点 | 工地 经历 节点（状态机） |
| 节点 → 验收 | 节点 通过 验收 |
| 角色 → 环节 | 角色 负责 环节 |
| Agent → 环节 | Agent 服务 环节 |

## 3. 项目生命周期状态机

`量房 → 设计 → 报价 → 签约 → 开工 → 水电 → 泥木 → 油漆 → 安装 → 验收交付`

- 第一阶段（获客→签单）覆盖：量房 → 设计 → 报价 → 签约
- 中控 Agent 依据当前节点路由任务、触发交接

## 4. 确定性规则（不进大模型的部分）

| 规则 | 说明 |
| --- | --- |
| 报价明细金额 = 工程量 × 单价 | 预算 Agent 用规则引擎计算 |
| 报价单总额 = Σ明细 + 管理费 − 优惠 | 同上 |
| 折扣超过阈值需总监审批 | 签约 Agent 触发审批流 |
| 节点顺序依赖（水电→泥木→油漆→安装） | 工程 Agent 排期约束 |
| 线索评分（需求真实性 + 意向度） | 评分 Agent 规则 + 模型 |

## 5. 本体 → 平台映射

1. **数据模型**：本体概念表 = 主数据 schema（所有 Agent 读写同一套表）
2. **状态机**：生命周期 = 中控 Agent 路由依据
3. **规则**：确定性引擎，不依赖大模型
4. **知识挂载**：每个概念下挂资料 = 知识库分类 = 数据需求清单的源头
