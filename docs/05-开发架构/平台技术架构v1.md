## 1. 总体形态

**Windows 本地单机起步 → 多公司上云后置。** Python 3.12 后端 + 本地 Web 工作台；SQLite 单文件数据库（零部署）；AI 走豆包 API（模型名/密钥配置化，可换本地小模型）；一切语义走配置包，代码零写死。

## 2. 技术栈选型（逐层）

| 层 | 默认建议 | 替代项（可调） | 理由 |
| --- | --- | --- | --- |
| 后端 | **FastAPI** | Flask / Django / 纯 CLI | 异步、自动文档、与原型同 Python 栈；CLI 兜底 |
| 前端工作台 | **简单 Web 页**（FastAPI 托管静态页+JS） | React+Vite（你的 Pi 驾驶舱体验） | 阶段1-2 快出闭环；驾驶舱后置 |
| 数据库 | **SQLite**（单文件） | MySQL / PostgreSQL | 单公司零部署；多公司再迁 |
| ORM | **SQLAlchemy** | 原生 sqlite3 | 换库不留债 |
| 配置 | **YAML**（terms/rules/extensions/workflow）+ manifest.json | 全 JSON（原型风格） | YAML 可读性好、好填 |
| 状态机 | **自研配置驱动**（workflow.yaml 节点+强约束锁定） | transitions 库 | 强约束（隐蔽工程不可跳过）需要自控 |
| Agent 运行时 | **中控 + 子 Agent（Python 类）+ 消息总线** | 插件化事件总线 | 直接复用原型 command_handler /pause /reject |
| 知识库 | **目录+关键词检索起步** | ChromaDB 向量 / Ollama embedding | 阶段3 先出可用；向量后置 |
| AI 模型 | **豆包 API**（起草/评分/总结） | 本地 Ollama 小模型 | 模型名/温度/密钥全配置化 |
| 通知/派单 | **站内待办（数据库）+ 复制/模板发送** | 企微机器人（M3b） | 阶段2 不依赖渠道 |
| 部署 | **start.ps1 → 浏览器本地端口** | Docker 上云 | 备份=文件备份（db+配置包+knowledge+沉淀） |
| 沉淀中心 | **表 sedimentation_items + 提炼物 md 目录双写** | 后置 UI | 先人工分拣 |

## 4. 数据模型（两张主表 + 三张辅助表）

| 表 | 关键字段 |
| --- | --- |
| customers（主表·客户CRM） | id, phone(脱敏), name, estate楼盘, layout户型, area面积, budget_range预算区间, style风格, intent_time意向时间, channel渠道, tags需求标签, score评分, status(线索/跟进/邀约/到店/派单/成交/流失), source来源, created_at |
| projects（主表·项目） | id, customer_id, designer设计师, summary需求摘要, status(量房/设计/报价/签约…八阶段), dispatched_at派单时间, created_at |
| messages（收件箱） | id, customer_id, direction(in/out), content, author(ai/sales), approve_status(draft/approved/rejected/sent), created_at |
| followups（跟进记录） | id, customer_id, channel方式, content, result结果, next_at下次跟进 |
| sedimentation_items（沉淀物） | id, category类别, title, description, condition适用条件, evidence证据, status(候选/已评审/已入内核/已剔除) |

## 5. Agent 运行时关键流程（人审后发）

```
收件箱：消息进来 → lead_agent 起草(draft) → 销售审批 approve/reject/edit → 发送(sent) → 记录
派单：客户达派单条件 → dispatch_agent 打包需求摘要 → 建项目(projects) → 站内待办通知设计师
指令：/pause /resume /reject（复用）+ 新增 /dispatch /approve /reject_msg
```

## 6. 安全与合规

1. 数据隔离：单公司单 db 文件，物理隔离，不共享
2. 手机号脱敏展示（部分打码）
3. AI 只起草不直发（人审后发，规避自动回复风险）
4. 沉淀只收提炼物（匿名化+抽象化），原始数据永不进池
5. 配置包只存语义，不含客户数据

## 8. 工程部件补全（v1.1 新增）

v1 覆盖"选型"，以下补齐"能开工、能验收、能长期跑"的工程件。

### 8.1 认证与权限（阶段 2 前定）
- users 表：id, 账号, 密码哈希, 角色(主管/销售/客服/设计师), 归属公司
- 权限矩阵：销售只见自己线索；主管可审批折扣/看全部/派单；客服可建档/起草
- 阶段 2 先做"单角色兜底"（默认全部走主管权限），角色分权后置

### 8.2 审计与日志（阶段 2 前定）
- audit_log 表：id, user, action(审批/驳回/修改/派单/发送), target(表+id), before/after, time
- 人审后发必须可追溯：谁批的、何时、原稿改了什么
- logs 目录轮转（单文件上限 + 保留 N 份）

### 8.3 定时任务（阶段 3 前定）
- SOP 提醒调度：每日扫 followups.next_at 到期项 → 生成站内待办
- 实现：main.py 后台线程（简单轮询）即可，不上重调度框架

### 8.4 API 契约（阶段 2 前定，≤10 个）
- POST /customers 建档｜GET /customers 列表（筛选/搜索）｜GET /customers/{id} 详情
- POST /messages 起草（AI）｜POST /messages/{id}/approve｜POST /messages/{id}/reject
- POST /dispatch 派单（建项目）｜GET /todos 待办｜GET /stats 看板
- 前后端以 JSON 契约对齐，前端页面照此开发

### 8.5 页面路由（阶段 2 前定）
登录 → 收件箱（审批队列）→ 客户列表 → 客户详情（需求+对话+跟进）→ 派单 → 看板

### 8.6 LLM 抽象层（阶段 2 前定）
- src/llm.py：封装 chat(prompt, system) / summarize(text)；provider 可插拔（豆包/Ollama）
- 业务代码只调 llm.py，切换模型只改 model_config.yaml

### 8.7 指标口径与采集（阶段 3 前定）
| 指标 | 口径 | 计算位置 |
| --- | --- | --- |
| 24h 首联率 | 线索建档后 24h 内 messages 有外发记录 / 建档线索数 | SQL 视图 |
| 响应时长中位数 | 客户消息→AI起草时间 与 →审批时间 的中位数 | messages 表 |
| 派单及时率 | 达条件线索 24h 内派单比例 | customers+projects |
| 线索→客户转化 | 派单数 / 线索数 | customers 表 |

### 8.8 测试与验证（分层）
1. schema 校验单测（配置包填错报错）
2. Agent 单测（lead/dispatch 各流程）
3. MVP 全链路验收脚本（3-5 条真实线索走通）
4. 阶段 4 业务指标核对（对账口径）

### 8.9 备份与恢复 + 初始化运维（阶段 1 做）
- init 脚本：建库建表 + 校验配置包 schema + 创建默认账号
- 备份清单：db/ + company_profiles/ + knowledge/ + sedimentation/ + logs/ + config/
- 一键备份脚本 backup.ps1（带日期戳）+ 恢复说明
- 健康检查：GET /health（进程/库/配置可读）

## 10. 四层记忆架构（v1.1 追加，详见《记忆架构v1-四层记忆.md》）

### 10.1 四层
| 层 | 内容 | 存储 |
| --- | --- | --- |
| L1 即时 | 会话上下文/待审草稿/任务状态 | 内存 + session 表（会话内） |
| L2 短 | 对话/跟进/审批记录 | messages/followups/audit_log（30天滚动） |
| L3 长（本体驱动） | 客户画像/公司语义/沉淀经验/知识库 | customers + 配置包 + sedimentation + knowledge |
| L4 文本 | 访谈笔记/复盘/提炼物（人可读 md） | memory/ 目录（Obsidian 兼容，YAML frontmatter 带本体元数据） |

### 10.2 流转
L1→L2（会话结束落库）→ L3（提炼画像/经验，准入4条）→ L4（物化为 md）；L4→L3（优质 md 评审后回流）。

### 10.3 新增组件
- memory_manager.py：四层读写/流转/归档/清理（阶段 2 骨架挂载）
- session 表：L1 会话上下文（阶段 2）
- memory/ 目录 + 记忆文件模板：concept_id/relation/state 元数据（阶段 3）
