# 四层记忆架构 v1（结合 Ontology 模式）

> 状态：v1（已被 v2《Otter 模式解读与结合》补充）｜更新：2026-09-30｜存放：HomeDesignGroup/docs/05-开发架构/
> 概念：即时记忆 · 短记忆 · 长记忆 · 文本记忆 = 四层；长记忆与文本记忆由**本体（Ontology）**驱动——概念/关系白名单/状态机是骨架。
> 注：用户表述"Otonage 模式"已确认为 **Otter 记忆模式**，详见《记忆架构v2-Otter模式解读与结合.md》。

---

## 1. 四层定义

| 层 | 内容 | 存储 | 生命周期 | 清理策略 |
| --- | --- | --- | --- | --- |
| L1 即时记忆 | 当前会话上下文：正在谈的客户、本条消息、待审批草稿、任务状态 | 内存 dict + session 表 | 会话内 | 会话结束即清 |
| L2 短记忆 | 近期对话/跟进/审批记录 | messages / followups / audit_log（SQLite） | 30 天滚动 | 滚动归档 |
| L3 长记忆（本体驱动） | 客户画像 · 公司语义（配置包）· 沉淀经验 · 知识库 | customers + company_profiles + sedimentation_items + knowledge | 长期 | 评审制增删 |
| L4 文本记忆 | 客户访谈笔记 · 谈单复盘 · 提炼物 · 话术迭代记录（人可读 md） | memory/ 目录（Obsidian 兼容） | 长期 | 人工维护 |

## 2. 本体链接（L3/L4 的灵魂）

- **L3 长记忆 = 本体实例库**：概念表（类）↔ 实体记录（个体）；关系白名单 ↔ 关联字段；状态机 ↔ 客户/项目状态。Agent 检索走"概念+关系+状态"语义，不是纯文本关键词。
- **L4 文本记忆 = 本体格式的记忆文件**：每个 md 带 YAML frontmatter 元数据（concept_id、relation、state、time、source），机器可检索、可回流结构化。
- **关系白名单**（学自 OBO P7）：part_of / preceded_by / has_participant / has_responsible / derived_from —— 记忆文件与长记忆用同一套关系，不跑偏。

## 3. 四层流转（记忆怎么"长大"）

```
L1 即时 ──会话结束落库(自动)──→ L2 短
L2 短 ──提炼画像/经验(准入4条)──→ L3 长
L3 长 ──物化为 md──→ L4 文本
L4 文本 ──优质md结构化回流(评审)──→ L3 长
```

- L1→L2：自动（会话/任务结束时 messages/followups 已落库）
- L2→L3：提炼客户画像（需求标签、偏好、历史）更新 customers；经验走沉淀准入 4 条进 sedimentation
- L3→L4：值得留档的结构化条目（如"该客户在意隐蔽工程工艺"）物化为记忆文件
- L4→L3：记忆文件中的优质内容（复盘结论、话术迭代）评审后结构化回长记忆

## 4. 管理组件：memory_manager

- 职责：四层读写 · 流转调度 · 归档 · 清理（各层策略见第 1 节）
- 挂载：main.py 中控里注册，Agent 通过 memory_manager 统一读写记忆
- 查询：Agent 提问时按"先即时→再短→再长/文本"的优先级取上下文（节省成本、命中精准）
