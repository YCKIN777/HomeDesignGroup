## 0. 一句话框架

**平台 = 内核（锁定）+ 配置（公司定制）+ 数据（隔离）+ 回路（沉淀共享）；按"资料→骨架→MVP→增强→试跑"五步推进，M3 拆两步防卡，阶段 0/1 并行提速，真实数据校准范围，业务指标检验效果。**

## 1. 总架构（锁定）

```
平台 = 内核 + 配置 + 数据 + 回路
├── 内核 v0.2（锁定）：八阶段主链 · 状态机主干 · 核心概念 · Agent框架 · 数据主线 · 沉淀原则
├── 配置包：术语/规则值/扩展字段/节点配置/知识库
├── 数据：客户CRM · 项目（起步两张表，隔离不共享）
└── 回路：试跑 → 提炼 → 沉淀中心（垃圾剔除）→ 反哺扩展点（封闭项不动）
```

## 2. 技术分层

| 层 | 内容 |
| --- | --- |
| 接入层 | 人工录入 + Excel 导入（兜底）；渠道直连（M3b，阶段3 后置） |
| 应用层 | 前端智能体工作台 · 统一收件箱 · 派单面板 · 看板 |
| 服务层 | Agent 运行时（中控+子Agent）· 规则引擎 · 知识库检索 · 消息通知（复用原型：消息总线、/pause /reject） |
| 数据层 | 客户CRM表 · 项目表 · 配置库 · 沉淀池 |

## 6. 业务指标（阶段 4 检验）

24h 首联率 · 响应时长中位数 · 派单及时率 · 线索→客户转化率

## 7. 迭代纪律（全程）

1. 封闭项变更 = 跨公司共性 + 评审 + 版本升级（v0.2→v0.3），禁随手改
2. 日常迭代只走扩展点：配置包 / 知识库 / 插件
3. 沉淀准入 4 条（有实例/可复现/不泄露/不违背强约束），季度复审剔垃圾
4. 流程假设错 → 先判扩展点还是封闭项，再动手
5. 试跑期降速保稳，迭代走沉淀流程
