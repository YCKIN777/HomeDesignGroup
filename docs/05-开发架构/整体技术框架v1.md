## 0. 一句话框架

**平台 = 内核（锁定）+ 配置（公司定制）+ 数据（隔离）+ 回路（沉淀共享）+ 记忆（本体驱动）；**
**本体系统是记忆的唯一骨架，读取按 Otter 模式（身份必载→当前对象自动载→按需检索带来源）；**
**五阶段推进：资料→骨架→MVP→增强→试跑；Windows 本地单机起步，壹城精工第一家试跑。**

## 2. 技术选型（锁定默认，决策点见第 11 节）

| 层 | 选型 |
| --- | --- |
| 后端 | Python 3.12 + FastAPI（+ 原型 CLI 兜底） |
| 前端 | 简单 Web 页（FastAPI 托管静态页+JS；React+Vite 后置可选） |
| 数据库 | SQLite（每公司一库）+ SQLAlchemy |
| 配置 | YAML 配置包（terms/rules/extensions/workflow/manifest）+ schema 校验 |
| 状态机 | 自研配置驱动（workflow.yaml，强约束锁定） |
| Agent | 中控 + 子 Agent + 消息总线（复用原型 /pause /resume /reject） |
| AI 模型 | llm.py 抽象层：豆包 API 默认，Ollama 可换（只改 model_config.yaml） |
| 知识库 | knowledge/ 目录 + 关键词检索起步；向量后置可选 |
| 部署 | start.ps1 本地启动 + 浏览器访问；备份=文件备份 |
| 记忆 | **本体系统唯一骨架，不引入其他记忆框架**（详见第 4 节） |

## 3. 本体系统（记忆的骨架）

| 组件 | 内容 | 对齐的标准 |
| --- | --- | --- |
| 术语注册表 terms.yaml | 每词条 {id, label, 定义"一个X其特征Y", 父类, 来源, 状态} | OBO P6 文本定义 / P12 命名唯一 |
| 关系白名单 | part_of / preceded_by / has_participant / has_responsible / derived_from + 领域关系（域/值域明确） | OBO P7 关系复用 |
| 状态机 workflow.yaml | 八阶段主干 + 节点配置（强约束：隐蔽工程不可跳过） | ODP 生命周期模式 |
| 沉淀中心 | 提炼准入 4 条（有实例/可复现/不泄露/不违背强约束）+ 季度复审剔垃圾 | OBO P19 术语稳定 |
| 记忆文件 | md + YAML frontmatter（concept_id/relation/state/time/source） | DOS-DP 式 YAML + 校验 |
| 配置校验器 | config_loader.py：填错当场报错 | DOS-DP validator |

## 4. 四层记忆（本体驱动 · Otter 读取 · 不加其他记忆方式）

| 层 | 内容 | 存储 | 生命周期 |
| --- | --- | --- | --- |
| L1 即时 | 会话上下文/待审草稿/任务状态 | 内存 + sessions 表 | 会话内，可续接 |
| L2 短 | 对话/跟进/审批记录 | messages/followups/audit_log | 30 天滚动（待确认） |
| L3 长 | 客户画像/公司语义/沉淀经验/知识库（本体结构化：概念↔实体·关系↔字段·状态机↔状态） | customers + 配置包 + sedimentation + knowledge | 长期，评审制 |
| L4 文本 | 访谈笔记/复盘/提炼物（人可读 md） | memory/ 目录（Obsidian 兼容） | 长期，人工维护 |

**读取模式（Otter 式，写入 memory_manager）：**
1. 身份必载：配置包语义 + 角色 prompt（每次新窗口必载，不占大 token）
2. 打开客户：自动载该客户 L2 短记忆
3. 提问时：按需检索 L3+L4（关键词+本体结构检索），top-k 命中，**答案带来源**
4. 会话内：本会话上下文保持（sessions 表）
5. 不加载：不把全部 L3/L4 塞进提示词

**流转**：L1→L2（会话结束落库）→ L3（提炼画像/经验，准入4条）→ L4（物化为 md）；L4→L3（优质 md 评审后回流）。

**约束**：不加其他记忆方式（不引 Mem0/Zep/外部向量库等）；记忆的一切结构由本体系统定义。

## 9. 安全与隔离

1. 数据隔离：每公司一库 + 独立 memory/ 目录，物理隔离
2. 语义共享：提炼物进公共沉淀中心（匿名化+抽象化），原始数据永不进池
3. 人审后发：AI 只起草，销售审批后发送；audit_log 全追溯
4. 手机号脱敏；配置包只存语义不含客户数据

## 10. 迭代与沉淀纪律

1. 封闭项变更 = 跨公司共性 + 评审 + 版本升级（v0.2→v0.3，CHANGELOG）
2. 日常迭代只走扩展点：配置包 / 知识库 / 记忆文件 / 插件
3. 沉淀准入 4 条 + 季度复审剔垃圾
4. 流程假设错 → 先判扩展点还是封闭项再动手
5. 记忆只加在本体系统上，不引其他记忆方式
