Otter 记忆模式 · 新开窗口读取流程
解读 Otter.ai + OtterBot · 2026-09-30
核心：新窗口 ≠ 失忆。身份必载 + 当前对象近期记忆自动载 + 其余按需检索（问到了才取，带来源）。
新开窗口读取顺序（罗列）
① 身份必载：SOUL.md / 公司配置包语义（术语+规则+扩展）+ 角色 prompt —— 每次必载，不占大 token
↓
② 当前对象自动载：打开某客户 → 自动加载该客户短记忆（近期对话/跟进/审批）
↓
③ 会话内上下文：本会话问答历史保持（sessions 表），可重开旧会话续接
↓
④ 提问时按需检索：RAG 检索长记忆（画像/沉淀/知识库）+ 文本记忆（memory 文件）→ top-k 命中 → 答案带来源（哪条记录/哪个文件）
↓
⑤ 可手动附加范围：@ 指定客户/渠道/楼盘/项目（对齐 Otter 的 "@ Add context"）
不做什么：不把全部长记忆/全部记忆文件塞进提示词（防 token 爆炸 + 噪音干扰）。
Otter 记忆架构 ↔ 四层记忆
· 身份/人设（SOUL） ↔ L1 之上的"常驻身份层"——公司语义必载
· AI Chat 会话上下文 ↔ L1 即时 + sessions 表
· 结构化提炼（摘要/决策/memories） ↔ L3 长记忆（本体结构化）
· 可检索语料（转写/频道/文件夹 ↔ vectors） ↔ L3+L4 按需检索（memory_retrieval.py）
· 来源标注 ↔ audit_log + 答案引用来源
· 每 Agent 独立 agent.db ↔ 每公司独立 db 文件（隔离，已对齐）
一句话：Otter 模式 = "身份必载 + 会话内上下文 + 按需检索带来源"。它告诉我们——新开窗口不是把记忆全背一遍，而是"记住你是谁 + 记得眼前这个客户 + 问到什么查什么、查到的带出处"。
