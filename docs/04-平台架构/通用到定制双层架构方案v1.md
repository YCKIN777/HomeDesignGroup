# 家装 AI 智能体平台 · 通用→定制 双层架构方案 v1

> 状态：探讨稿 v1｜更新：2026-09-29｜存放：HomeDesignGroup/docs/04-平台架构/
> 一句话：**先立通用骨架（行业通用、流程正确），数据与语义作为"定制配置"后补；将来对任何一家公司，通过补数据 + 改本体语义关系完成私人化定制，架构代码不动。**

## 1. 三层结构

```
① 通用内核（不改）          —— 行业通用，任何家装公司都成立
   ├── 通用本体（概念骨架 + 关系 + 八阶段状态机）
   ├── Agent 框架（中控 + 六工种 + 人审后发 + 审批点）
   ├── 主数据模型（线索→客户→项目→报价→材料→工地→验收）
   ├── 知识库分类骨架（工艺/材料/案例/话术）
   └── 全流程步骤（八阶段 SOP 骨架）

② 定制机制（可配置的中间层）—— 定制的入口，全部参数化
   ├── 术语映射表：公司叫法 ↔ 通用概念
   ├── 扩展概念/字段：公司专属属性（套餐档位、质保金、特殊工艺）
   ├── 规则配置表：折扣阈值、付款比例、SOP 节奏、质保年限
   ├── 状态机配置：增删节点（强约束节点锁定，如水电不可跳过）
   └── 公司配置包：一家公司一个包，切换公司=换包

③ 公司实例（实例化层）      —— 现在还没有，将来填充
   ├── 数据库实例（具体表 + 真实数据）
   ├── 公司语义定义（术语、规则值、节点划分、组织架构）
   ├── 知识库内容（话术、材料库、工艺标准、案例）
   └── 历史数据（报价单、合同、工地记录，用于校准 AI）
```

## 2. 定制原则

1. **骨架封闭、叶子开放**：八阶段流程、状态机主干、核心概念关系是"封闭"的（改了全链路就崩）；属性、术语、规则值、扩展概念是"开放"的（随便加）。
2. **一切语义走配置，不硬编码**：公司里所有"叫法不同、数值不同、节点不同"的地方，全部进配置，代码里不写死。
3. **数据是实例，不是架构**：架构只定义"数据应该长什么样"（元模型/schema），不依赖任何一家公司的真实数据。
4. **定制不重写，只填配置**：做新公司 = 生成新的公司配置包（数据 + 语义 + 规则 + 知识库），内核零改动。

## 3. 与已有资产的关系

| 已有资产（本会话产出） | 归属 |
| --- | --- |
| 领域本体 v0.1（概念/关系/状态机） | ① 通用内核（骨架已立） |
| 家装全链路业务逻辑（八阶段 + 三流 + 审批点） | ① 通用内核（逻辑已立） |
| 全流程步骤清单 v1（每阶段每步） | ① 通用内核（SOP 骨架已立） |
| 数据需求清单 v1（13 类数据 + 优先级） | ② 定制机制（定制的"输入清单"） |
| 施工工艺与验收资料库（17 个来源网站文档） | ③ 公司实例（第一批知识库内容） |
| 待校准清单（报价结构/付款比例/质保等） | ② 定制机制（规则的"待填值"） |

**结论**：通用内核骨架已经立起来了；定制机制的"槽位"已定义；现在就差真实公司的数据与语义去填——这正好是你说的"现在没有数据，先立架构"。

## 4. 下一步建议

1. 把领域本体升级为 **v0.2 通用版**：明确标出哪些是"内核封闭项"、哪些是"定制开放项"（术语/规则/扩展字段的槽位）
2. 定义**定制配置包的格式**（术语表、规则表、扩展字段、状态机配置的字段结构）——这是"以后可修改"的载体
3. 其余（数据库选型、Agent 实现、知识库灌入）等在定完定制机制后按优先级推进
